# MarginWatch

Vendor price-file sync & margin guard for IT distribution. Distributors receive
price files from dozens of vendors daily — MarginWatch parses them, flags every
margin-breaking change before it's applied, and audits who changed what.

Built as a portfolio piece for IT-distribution operations (Java full-stack).

## Live demo

| Role | Email | Password | Can do |
|---|---|---|---|
| Admin | `admin.demo@marginwatch.in` | `Demo@Admin2026` | Everything: breach overrides, selling-price edits, policies |
| Analyst | `analyst.demo@marginwatch.in` | `Demo@Analyst2026` | Upload files, map columns, apply normal rows |
| Viewer | `viewer.demo@marginwatch.in` | `Demo@Viewer2026` | Read-only (GET-only, enforced server-side) |

Demo workspace is seeded with four vendors, 63 products, three price files
(including one pending file with every flag type live in the diff preview) and
a populated audit trail. Every action is written to the audit log.

## How it works

1. **Upload** a vendor CSV/XLSX price file. Parsing runs in the background
   (CSV via Apache Commons CSV, XLSX via Apache POI), with a 5 MB / 5,000-row cap.
2. **Column mapping** — each vendor's headers are mapped once to target fields
   (SKU / DESCRIPTION / COST_PRICE) and reused. Costs like `₹ 52,500.00` are
   cleaned automatically. If over half a file fails to resolve against the
   catalog, the file is marked FAILED and the mapping editor re-opens — stale
   mappings are caught, not silently mis-applied.
3. **Diff preview** — every row is flagged before anything is applied:
   - `OK` — change keeps margin at/above the policy floor
   - `BREACH` — resulting margin below floor (category policy overrides the
     global floor), or new cost ≥ selling price (loss — always a breach)
   - `NEW_SKU` — SKU not in the catalog (skip-only, never auto-created)
   - `NOT_FOUND` — unresolvable row / SKU of another vendor
   - `DUPLICATE` — later occurrence of a SKU already seen in the same file
4. **Apply** per row or in bulk, from PENDING only (conditional updates, so
   concurrent applies lose the race with a 409). Applying a breach requires a
   typed override reason. One transaction moves the cost, updates the row and
   writes audit entries.
5. **Audit** — insert-only log of every applied price, override (with reason),
   selling-price edit, policy change and mapping change.
6. **Report** — per-file XLSX export (POI streaming). **Dashboard** — applied
   changes/day, margin by category, vendor×category breach heatmap, top movers.

Selling prices are ours — vendor files never touch them; only admin edits can
change them, and those are audited too.

## Stack

Java 21 · Spring Boot 3.5 · Spring Security + JWT (24h, BCrypt) · Spring Data
JPA/Hibernate · Apache POI · Commons CSV · JUnit 5 · JaCoCo · springdoc (Swagger)
· Maven · React 18 + Vite · Chart.js · custom CSS (no UI framework) · H2 (tests)
· PostgreSQL (Neon) · Docker · Render.

One Spring Boot fat JAR serves both the React SPA and the REST API — same
origin, no CORS. Coverage: 94% line / 75% branch.

## Run locally

```bash
mvn spring-boot:run          # H2 in-memory, seed loads on first boot
# SPA dev: cd frontend && npm install && npm run dev  (proxies :8080)
```

Swagger: <http://localhost:8080/swagger-ui.html>

## Deploy (Render + Neon)

Single Docker web service (see `Dockerfile`, `render.yaml`). PostgreSQL on
Neon free tier (`sslmode=require`), keep-alive cron pinging `/actuator/health`
during IST business hours. Set `SPRING_DATASOURCE_URL/USERNAME/PASSWORD`,
`JWT_SECRET` (auto-generated by Render), `ADMIN_PASSWORD`.

## Design decisions / trade-offs

- `ddl-auto=update` for simplicity; real production would use Flyway migrations.
- Timestamps are persisted as IST wall-clock (all reporting boundaries are IST).
- The raw uploaded file is not stored — what persists is the parsed row set
  with its diff outcome; a failed file is re-uploaded after fixing the mapping.
- Demo accounts are full-access on sample data (unlike a read-only demo) —
  the apply/override/audit workflow is the point, and the audit log records
  everything the demo does.
